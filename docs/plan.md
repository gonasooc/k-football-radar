# 제품 기획

무엇을 누구를 위해 만드는지와 제품의 범위·정책을 다룹니다. 개별 작업의 구현 순서와 진행 상황은 `docs/work/`의 작업 문서에서 관리합니다. 초기 기획의 전체 원문은 [docs/mvp-plan.md](mvp-plan.md)에 있습니다.

## 목적과 사용자

Korea Football Radar는 대한축구협회(KFA), 문화체육관광부, 대한체육회, 회장 선거와 정관·감사 같은 한국 축구 거버넌스 흐름을 한 화면에서 빠르게 훑고 원문으로 확인하려는 사람을 위한 공개 모니터링 도구다.

핵심 사용자는 프로젝트 소유자 본인, 개혁 논의를 따라가는 축구 팬, 관련 기관의 움직임을 추적하려는 독자다. 사용자는 최근 변화를 확인하고, 어떤 이슈와 인물이 활발한지 파악하고, 모든 항목을 원문 링크로 검증한다. 홍보성 랜딩 페이지나 커뮤니티 플랫폼이 아니다.

## 이번 범위

- 제공할 것: 뉴스·공식자료·유튜브 메타데이터의 자동 수집, 이슈·인물 자동 태깅, 홈/뉴스/유튜브/트래킹/출처 화면, 이슈·인물 상세 화면, 원문 아카이브, 데이터 검증, 예약 수집 워크플로, R2 데이터 발행과 맥미니 홈서버 운영.
- 이번에는 다루지 않을 것: 회원가입·로그인, 댓글, 제보 시스템, 관리자 CMS, 관계형 DB, Slack·Discord·Telegram 알림, AI 요약과 AI 판정, 기사 본문 전체 저장, 유튜브 자막 수집, 관계도 그래프, 수동 검수 워크플로, 읽음 처리·개인 북마크. 근거: [docs/mvp-plan.md](mvp-plan.md) 5절.
- 성공을 확인하는 기준: 사용자가 최근 수집 항목과 이슈·인물별 흐름을 화면에서 확인하고 모든 항목에서 원문으로 이동할 수 있다. 운영 기준으로는 `https://k-football-radar.app/api/health`가 200과 `data.source: "r2"`를 반환하고, 예약 수집 워크플로가 계속 성공한다.

이 범위는 MVP와 2026-07-17·2026-07-18의 YouTube 확장 결정, R2 데이터 발행, 홈서버 배포까지 구현·운영 중인 상태다. 남은 외부 작업은 [docs/remaining-work.md](remaining-work.md)에서 관리한다.

2026-09-21 결정: 당분간 기능을 늘리지 않고 유지보수만 한다. 새 기능은 이 범위에 추가하기 전에 별도로 결정한다.

## 핵심 기능과 사용자 흐름

상단 메뉴는 `홈 / 뉴스 / 유튜브 / 트래킹 / 출처` 다섯 개다. 화면별 동작과 라우트는 [docs/architecture.md](architecture.md), 자세한 설명은 [docs/system-overview.md](system-overview.md) 5절에 있다.

- 홈(`/`): 검색 없이 최신 뉴스·공식자료 6건과 최신 유튜브 영상 6건을 나눠 보여주고 각 전문 목록으로 보낸다.
- 뉴스(`/news`): 검색·유형·범위·정렬·이슈·인물 필터를 제공한다. 같은 사건을 다룬 기사는 대표 기사와 관련 기사로 묶어 보여준다.
- 유튜브(`/youtube`): 뉴스와 같은 필터를 공유하되 자료 유형 필터 대신 `선별 채널 / 전체 채널` 범위를 제공하고, 썸네일·채널·발행일·재생 시간을 표시한다.
- 트래킹(`/tracking`): 이슈 탭과 인물 탭에서 연결된 항목 수를 보여주고 `/issues/[id]`, `/people/[id]` 상세로 보낸다.
- 출처(`/sources`): 수집 출처, 발행처·채널 통계와 묶지 않은 전체 원문 링크를 감사 가능한 형태로 보여준다.

모든 항목은 제목 자체가 원문 링크이며, 사용자는 어느 화면에서든 한 번에 원문으로 이동해 사실을 확인한다.

## 제품 정책과 제약

확정된 정책이다. 구현 위치와 검증 방법은 [docs/specs.md](specs.md)에서 관리한다.

- 저작권: 기사 본문 전체, 기사 이미지 원본, 유튜브 영상 파일과 자막을 저장하지 않는다. 제목, 짧은 설명, 출처, 발행·수집 시각, 태그, 원문 링크, 썸네일 URL만 저장한다.
- 명예훼손 방지: 자동으로 단정적 부정 라벨을 붙이지 않는다. 인물 화면은 ‘논란’이 아니라 ‘언급 기록’으로 표현한다. 위험한 단정 라벨은 `pnpm run validate:data`에서 거부한다.
- 검증 가능성: 모든 항목은 확인 가능한 `http(s)` 원문 링크를 가진다. 자동 태그는 키워드 규칙의 결과이므로 틀릴 수 있다고 전제하고 원문 확인을 유도한다.
- 데이터 품질: 데이터가 이상하면 수집량을 늘리기보다 필터와 검증을 먼저 고친다. `/sources`의 원문 목록은 묶지 않고 모든 항목을 유지한다.
- 유튜브 채널 정책: `preferred`는 uploads playlist를 별도 수집하고 `선별 채널` 범위에 노출하며, 목록에 없는 채널은 `unlisted`로 최대 secondary, `blocked`는 수집과 기존 데이터에서 제외한다. 채널 상태는 자동으로 바뀌지 않고 사람이 `data/youtube-channels.json`을 고쳐야 바뀐다.
- Shorts와 라이브: 최소 재생 시간 기준을 두지 않는다. 명시적 표식이나 `/shorts/{videoId}` 확인으로 확정된 Shorts만 제외하고, 불명확하면 보존하는 fail-open 정책이다. 라이브·예약 방송·라이브 다시보기는 일반 영상과 같은 관련도 규칙으로 수집한다(2026-07-29 변경, `tests/youtube.test.ts`에서 확인).
- 보존 정책: 발행 90일이 지난 항목을 버리고, 주요 뉴스·공식자료 6,000건, 보조 뉴스 3,400건, 유튜브 1,200건의 독립 예산으로 최신순 보존한다. 한 종류가 다른 종류를 밀어내지 않게 하려는 결정이다(`lib/item-retention.ts`). 2026-09-21에 상한을 올려 세 버킷 모두 90일 창이 먼저 걸리도록 맞췄다. 이전 상한(4,000 / 700 / 500)에서는 보조가 20일, 유튜브가 45일에서 잘렸다([docs/work/W-002-main-item-retention-review.md](work/W-002-main-item-retention-review.md)).
- 운영 경계: 수집 API 키는 GitHub Actions에서만 사용하고 홈서버 런타임에 두지 않는다. 수집 데이터 변경은 R2로 반영하고 앱 이미지는 코드가 바뀔 때만 다시 배포한다.
